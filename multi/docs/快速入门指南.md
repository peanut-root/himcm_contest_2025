# 快速入门指南

本指南将帮助您在 5 分钟内开始使用消防员巡视路径优化系统。

## 📦 第一步：安装

### 1.1 检查环境

确保您的系统安装了 Node.js 18 或更高版本：

```bash
node --version  # 应该显示 v18.0.0 或更高
npm --version   # 应该显示 9.0.0 或更高
```

### 1.2 安装项目

```bash
# 进入项目目录
cd himcm

# 安装依赖包
npm install

# 构建 TypeScript 代码
npm run build
```

## 🎯 第二步：运行第一个示例

### 2.1 基本场景

运行预配置的 6 房间办公楼场景：

```bash
npm run example
```

## 🚀 第五步：尝试其他场景

### 5.1 冗余检查模式

某些关键房间需要两个不同的消防员检查：

```bash
npm run example:redundancy
```

**场景**：
- 3 个消防员
- 6 个房间（服务器机房和化学品存储需要冗余检查）
- 完成时间：220秒

**查看结果**：
```bash
cat redundancy-results.json | grep -A 10 "roomsInspected"
```

您会发现 R1 和 R3 被两个不同的消防员检查了。

### 5.2 返回出口模式

确保所有消防员完成后返回安全出口：

```bash
npm run example:return
```

**场景**：
- 2 个消防员
- 4 个仓库房间
- 自动返回最近的出口

**可视化**：
```bash
npm run viz:return
open return-timeline.html
```

您会在时间线末尾看到返回出口的移动操作。

### 5.3 组合模式

冗余检查 + 返回出口：

```bash
npm run example:combined
```

这是最完整的安全协议执行。

## 🛠️ 第六步：自定义场景

### 6.1 修改参数

您可以直接使用 CLI 命令自定义参数：

```bash
npm run plan -- \
  -b examples/basic-6-room.json \
  -a 3 \
  -r R1,R2,R3 \
  --return-to-exit \
  -o my-results.json
```

**参数说明**：
- `-b` 建筑配置文件
- `-a` 消防员数量（这里是 3 个）
- `-r` 需要冗余检查的房间（R1, R2, R3）
- `--return-to-exit` 启用返回出口
- `-o` 输出文件名

### 6.2 创建自己的建筑

创建新文件 `my-building.json`：

```json
{
  "id": "my-building",
  "nodes": [
    {"id": "exit-main", "kind": "EXIT", "x": 0, "y": 0},
    {"id": "corridor-1", "kind": "CORRIDOR", "x": 10, "y": 0},
    {"id": "door-R1", "kind": "DOOR", "x": 10, "y": 5, "label": "Room 1 Door"}
  ],
  "edges": [
    {"id": "e1", "from": "exit-main", "to": "corridor-1", "baseTime": 10},
    {"id": "e2", "from": "corridor-1", "to": "door-R1", "baseTime": 5}
  ],
  "rooms": [
    {"id": "R1", "doorNode": "door-R1", "verifyTime": 30, "label": "Office 1"}
  ],
  "entrances": ["exit-main"],
  "exits": ["exit-main"],
  "metadata": {
    "name": "My Custom Building",
    "description": "A simple test building"
  }
}
```

**验证配置**：
```bash
npm run validate my-building.json
```

**运行规划**：
```bash
npm run plan -- -b my-building.json -a 1 -o my-results.json
```

## 🎓 第八步：理解输出

### 8.1 JSON 结构

`results.json` 包含以下主要部分：

```json
{
  "missionId": "建筑 ID",
  "makespan": "总完成时间（秒）",
  "routes": [
    {
      "agentId": "消防员 ID",
      "actions": [
        {
          "type": "MOVE | ENTER | INSPECT | EXIT_ROOM",
          "startTime": "开始时间",
          "endTime": "结束时间",
          "location": "位置"
        }
      ],
      "roomsInspected": ["检查的房间列表"],
      "totalTime": "该消防员的总时间"
    }
  ],
  "metrics": {
    "makespan": "总完成时间",
    "redundancyCoverage": {
      "rate": "冗余覆盖率（0-1）"
    },
    "loadBalance": {
      "stdDev": "时间标准差（越小越平衡）"
    }
  },
  "validation": {
    "valid": "是否通过所有验证",
    "coverage": "覆盖率检查",
    "redundancy": "冗余检查",
    "conflicts": "冲突检查"
  }
}
```

### 8.2 行动类型

- **MOVE**: 在走廊中移动
- **ENTER**: 进入房间
- **INSPECT**: 检查房间（关键活动）
- **EXIT_ROOM**: 离开房间

### 8.3 性能指标

- **Makespan**: 所有消防员完成的最长时间
  - 越小越好
  - 目标：最小化 makespan

- **冗余覆盖率**: 完成的冗余检查比例
  - 1.0 = 100% 完成
  - < 1.0 = 部分未完成（验证失败）

- **负载均衡**: 消防员之间的工作分配
  - 标准差越小 = 分配越均衡
  - 理想情况下接近 0

## ⚠️ 常见问题

### 问题 1: 安装失败

```bash
npm ERR! Cannot find module 'xyz'
```

**解决方案**：
```bash
rm -rf node_modules package-lock.json
npm install
```

### 问题 2: 构建错误

```bash
tsc: error TS2304
```

**解决方案**：
```bash
npm run build -- --force
```

### 问题 3: 验证失败

```
✗ Building validation failed
```

**解决方案**：
- 检查 JSON 语法（使用 jsonlint.com）
- 确保所有节点 y 坐标 >= 0
- 确保所有引用的节点都存在
- 使用 `--type building` 明确指定类型

### 问题 4: 无可行解

```
ILP solver returned infeasible solution, falling back to greedy
```

**原因**：
- 冗余房间数量太多
- 消防员数量太少
- 约束条件过于严格

**解决方案**：
- 增加消防员数量
- 减少冗余房间
- 系统会自动降级到贪心算法
