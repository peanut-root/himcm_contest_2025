# Feature Specification: Web Demonstration Application

**Feature Branch**: `003-web-demo`
**Created**: 2025-11-12
**Status**: Draft
**Input**: User description: "Build a web application for demonstrating the solution already implemented in the first spec '001-firefighter-patrol-optimization'"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Load and Visualize Pre-Computed Routes (Priority: P1)

Users want to see the optimization results visually on a building layout with animated agent movements, using the 6-room office layout from the existing implementation.

**Why this priority**: This is the core demonstration value - showing how the optimization works visually. The solution is already computed by the CLI, the web app just needs to display it interactively.

**Independent Test**: Load the basic-6-room.json building and its results.json output, display the building layout, click play, and verify agents animate along their patrol routes.

**Acceptance Scenarios**:

1. **Given** user opens the web application, **When** the page loads, **Then** the 6-room office layout (2 exits, 1 hallway, 6 offices) is displayed with rooms labeled
2. **Given** the building is displayed, **When** user clicks "Load Results", **Then** pre-computed patrol routes from the CLI tool are loaded and ready for playback
3. **Given** routes are loaded, **When** user clicks "Play Animation", **Then** 2 agents (firefighters) move along their assigned routes on the building layout
4. **Given** animation is playing, **When** agents visit rooms, **Then** rooms change color to show inspection status (pending→in-progress→completed)
5. **Given** animation completes, **When** user views the summary panel, **Then** makespan, total path length, and coverage statistics are displayed

---

### User Story 2 - Control Animation Playback (Priority: P2)

Users want to control the animation speed and timeline to better understand the patrol sequence and timing.

**Why this priority**: Interactive controls make the demonstration more engaging and allow users to focus on specific aspects of the solution.

**Independent Test**: Load results, start animation, pause mid-execution, change speed, scrub timeline, and verify agents respond correctly to all controls.

**Acceptance Scenarios**:

1. **Given** animation is playing, **When** user clicks "Pause", **Then** agents freeze at their current positions and can be resumed later
2. **Given** animation is playing, **When** user adjusts speed slider (0.5x to 3x), **Then** agents move proportionally faster or slower
3. **Given** animation is paused, **When** user drags the timeline scrubber, **Then** agents jump to positions corresponding to that time in the mission
4. **Given** animation reaches the end, **When** user clicks "Restart", **Then** animation resets to the beginning with all rooms returning to pending state

---

### User Story 3 - Compare Different Scenarios (Priority: P3)

Users want to load and compare different pre-computed scenarios (basic, redundancy, return-to-exit, multi-agent) to see how the optimization changes.

**Why this priority**: Demonstrates the flexibility of the solution and shows how different configurations affect the results.

**Independent Test**: Load basic-6-room results, then load redundancy-scenario results, and verify that display updates to show 3 agents with 2 rooms inspected twice.

**Acceptance Scenarios**:

1. **Given** user is viewing one scenario, **When** user selects "Redundancy Scenario" from the dropdown, **Then** building layout updates to show 3 agents and redundant room markers
2. **Given** redundancy scenario is loaded, **When** animation plays, **Then** user can observe that specific rooms are visited by 2 different agents
3. **Given** user selects "Return to Exit" scenario, **When** animation completes, **Then** agents animate their return paths back to exit locations
4. **Given** multiple scenarios available, **When** user switches between them, **Then** metrics panel updates to show different makespan and path length values

---

### Edge Cases

- What happens if user tries to scrub timeline while animation is playing?
- How does the app handle very fast playback speeds (3x) with smooth rendering?
- What if pre-computed results file is missing or corrupted?
- How does the UI indicate which rooms are pending vs. completed when paused?
- What happens if the building layout in results doesn't match the expected 6-room office configuration?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST load and display the 6-room office building layout (2 exits, 1 central hallway, 6 offices as shown in layout.png)
- **FR-002**: System MUST load pre-computed route optimization results from JSON files generated by the CLI tool (results.json, redundancy-results.json, etc.)
- **FR-003**: System MUST validate loaded results match the displayed building configuration before animation
- **FR-004**: System MUST display building layout with rooms labeled by ID (R1-R6), exits marked clearly, and hallway connections shown
- **FR-005**: System MUST animate firefighter agents moving along their assigned patrol routes with visual indicators (colored circles/icons)
- **FR-006**: System MUST update room colors to indicate inspection state: yellow (pending), blue (in-progress), green (completed)
- **FR-007**: System MUST display agent labels/numbers (A1, A2, etc.) that move with the agents during animation
- **FR-008**: System MUST provide playback controls: Play, Pause, Restart buttons
- **FR-009**: System MUST provide a speed control slider ranging from 0.5x to 3x normal speed
- **FR-010**: System MUST provide a timeline scrubber showing current time and allowing users to jump to any point in the mission
- **FR-011**: System MUST display a metrics panel showing: makespan (total time), individual agent completion times, total path length, and coverage percentage
- **FR-012**: System MUST support loading different pre-computed scenarios via dropdown menu (basic, redundancy, return-to-exit, multi-agent)
- **FR-013**: System MUST display the current scenario name and description when loaded
- **FR-014**: System MUST show tooltips when hovering over agents displaying: agent ID, current action, elapsed time
- **FR-015**: System MUST show tooltips when hovering over rooms displaying: room ID, inspection status, which agent(s) visited
- **FR-016**: System MUST highlight the current path segment being traversed by each agent
- **FR-017**: System MUST work entirely in the browser (static site, no backend server required)
- **FR-018**: System MUST gracefully handle missing or invalid results files with clear error messages
- **FR-019**: System MUST maintain smooth animation at 30 FPS for all supported playback speeds
- **FR-020**: System MUST be responsive and work on desktop browsers with minimum 1024px width

### Key Entities

- **BuildingLayout**: The 6-room office floor plan with hallway, 2 exits, and 6 offices positioned as shown in layout.png
- **PreComputedResults**: JSON output from the CLI tool containing routes, actions, timestamps, and metrics
- **AnimatedAgent**: Visual representation of a firefighter with position, current action, and route history
- **Room**: A space in the building with ID, position, and inspection state
- **AnimationController**: Manages playback state (playing/paused), current time, speed, and timeline scrubbing
- **MetricsDisplay**: Shows mission statistics including makespan, path lengths, and coverage rates

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Users can understand the patrol optimization within 30 seconds of watching the animated demonstration
- **SC-002**: Animation runs smoothly at 30 FPS with no visible lag or stutter for the 6-room scenario
- **SC-003**: Users can successfully load and switch between 4 different pre-computed scenarios without errors
- **SC-004**: 90% of demonstration viewers can identify which rooms were inspected by which agents after one viewing
- **SC-005**: Playback controls (play, pause, speed, scrub) respond within 100ms of user interaction
- **SC-006**: Application loads and displays initial building layout within 2 seconds on standard broadband connection
- **SC-007**: Users can pause animation and inspect any room's status within 5 seconds
- **SC-008**: Application works on all major desktop browsers (Chrome, Firefox, Safari, Edge) without compatibility issues
- **SC-009**: Users can identify the makespan and understand why it represents the bottleneck agent within 1 minute
- **SC-010**: Application file size remains under 5MB total (including all assets) for fast loading

## Assumptions

- Users have access to a modern desktop browser with JavaScript enabled and HTML5 Canvas support
- Pre-computed results files are available and correctly formatted (generated by the existing CLI tool)
- Users are viewing demonstrations on desktop or laptop screens (not mobile/tablet)
- The building layout matches the 6-room office configuration shown in layout.png
- Users have basic computer skills (mouse control, button clicking)
- Internet connection is available for initial app loading (static assets), but no backend server is required
- Users understand basic fire safety concepts (patrol, inspection, room coverage)
- The demonstration is for educational/presentation purposes, not for production mission planning
- Animation performance is acceptable on hardware from the last 5 years

## Out of Scope

- Creating or editing building layouts (use existing 6-room office layout only)
- Running new optimizations (use pre-computed results from CLI tool)
- Real-time optimization or route calculation in the browser
- Mobile or tablet optimization (desktop-only experience)
- User accounts, authentication, or cloud storage
- Saving custom scenarios or annotations
- 3D visualization or multi-floor buildings
- Integration with real-time sensor data
- Exporting videos or screenshots of animations
- Accessibility features beyond standard browser support
- Multi-language support (English only)
- Advanced animation features (camera following agents, cinematic effects)
- Editing or modifying pre-computed routes
- Running CLI commands from the web interface
